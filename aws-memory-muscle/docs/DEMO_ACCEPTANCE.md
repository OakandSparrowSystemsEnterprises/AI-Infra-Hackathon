# Demo Acceptance Contract

A valid demonstration starts from a reproducible code failure in a disposable repository and finishes with a governed GitHub effect plus durable learning evidence.

Run one must show current state entering Hotdata, historical context queried from Cognee/HydraDB, remediation executing inside Tenki, tests running, Snyk evidence produced, an exact Action Envelope sent to Gatekeeper, a permitted or transformed effect executed through the controlled actuator, and a Learning Event persisted. The successful procedure must be available to Rote after the run.

Run two must recreate the same failure class with fresh state. The system must use prior memory and/or Rote to reduce rediscovery while still querying current state, rerunning validation, producing fresh security evidence, and obtaining a fresh Gatekeeper decision.

A HOLD or DENY demonstration should be available if time permits. An authority outage or malformed response must fail closed.

The demo is not accepted if any sponsor is present only as an unused import, if Tenki can directly bypass Gatekeeper to write to GitHub, if Rote replay skips fresh authorization, if prior authorization is reused, or if the event-created work cannot be distinguished from preexisting Gatekeeper technology.
