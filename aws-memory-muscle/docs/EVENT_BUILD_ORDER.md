# Event Build Order

The build is optimized around one complete vertical before breadth.

Phase A begins only after the organizer opens hacking. Wire the minimum RocketRide pipeline with one agent, one Cognee memory tool, one HydraDB durable-state path, one Hotdata current-state path, and one Tenki execution tool. The goal is a real read-only diagnosis against a disposable demo repository.

Phase B adds one bounded remediation path inside Tenki: clone or checkout, modify one known file, run one deterministic test command, collect a diff, and return evidence. Do not add GitHub write credentials to Tenki.

Phase C adds Snyk as evidence and creates the exact Action Envelope for a single consequential effect. Wire the external Gatekeeper call. HOLD or DENY must stop. ALLOW may execute only if the action digest matches. TRANSFORM must execute only the transformed action returned by authority.

Phase D adds the controlled GitHub effect, preferably opening a branch/PR rather than merging or deploying. Seal and persist the outcome.

Phase E writes the Learning Event to Cognee and HydraDB and captures the successful method through Rote. Re-run the same failure class with fresh state. The second run must visibly improve while still requesting fresh authority.

Only after the full vertical works should the team add richer UI, extra failure classes, telemetry, polish, additional actions, or broader sponsor use.

The submission gate is a live two-run proof: run one learns; run two reuses what was learned; both perform fresh security checks and fresh authorization.
